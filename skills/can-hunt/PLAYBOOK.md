# PLAYBOOK: сценарии поиска сигналов в CAN

Сценарии для Claude (навык `can-hunt`). Для каждого сигнала: подготовка и безопасность, готовые команды,
анализ, чего ожидать, как подтвердить. Готовых ID конкретных машин здесь нет: они разные у каждой марки, модели и года.

Запуск инструментов (в Bash всегда полностью, в кавычках):

```
python "${CLAUDE_SKILL_DIR}/scripts/car.py" …
python "${CLAUDE_SKILL_DIR}/scripts/canhunt.py" …
```

Ниже для краткости `car.py` и `canhunt.py`. Все `car.py ask` запускать **в фоне** (`run_in_background: true`) и ждать
уведомления. Вход анализа `latest` означает последнюю сессию. Можно указать и папку сессии, которую печатает `car.py session`.

## Общие правила

**Безопасность** (подробно — в SKILL.md §0): двигатель только на стоянке, P или нейтраль, ручник затянут. Водителю в
движении ничего не поручать: езду ведёт пассажир у ноутбука или делаем запись без инструкций. Руль крутить на месте.
Холодный двигатель — не выше ~2000 об/мин. Всё, что можно, делаем при включённом зажигании **без запуска двигателя**.

**Аккумулятор.** Зажигание без двигателя дольше ~15–20 минут (несколько сигналов подряд) разряжает аккумулятор, а
пока сниффер включён, контроллер не засыпает и держит шину. Делай паузы (зажигание выключить на пару минут) или, если
это безопасно, прогрей двигатель на холостых; после эксперимента — `car.py sniff off`. Иначе машина может не
завестись, и §1/§14 станут невозможны.

**Связь с контроллером.** После запуска двигателя (стартер просаживает питание) и после любого обрыва USB —
`car.py status`: сниффер ВКЛ, «молча», кадр/с > 0. `ask`/`wait` с кодом 6 — кадры не пишутся (SKILL §9).

**Фаза «держу».** Каждый уровень или состояние оформляется парой шагов, чтобы переход не попал в фазу:

```
car.py ask "Выжми газ наполовину и держи. Когда держишь ровно — нажми «Держу»." --buttons "Держу=pedal50,Не получается"
car.py ask "Держи ещё 5 секунд, потом нажми «Отпустил» и отпусти педаль." --buttons "Отпустил=-"
```

Фаза длится от первого нажатия до второго. Держать 5–10 с. Каждое состояние повторять минимум дважды, а для битов
3 раза: вкл → выкл → вкл → выкл → вкл → выкл. Повтор можно назвать той же фазой, анализ объединит отрезки.
Если что-то сбилось, закрой фазу (`car.py phase -`) и повтори шаг.

**Уровни числового сигнала — не по возрастанию.** Например idle → 2000 → 1500 → idle, а не idle → 1500 → 2000:
при фазах строго по возрастанию таймер или «пробег» совпадает с эталоном так же хорошо, как сигнал.

**Отметки для кнопок и коротких событий.** Сначала «Отметка», потом действие в течение 1–2 с (или наоборот — `marks`
сам подбирает сдвиг окна относительно отметок в пределах ±3 с). Повторов 5 и больше:

```
car.py ask "5 раз подряд: нажми «Отметка — сейчас!», сразу нажми кнопку «+» на руле и подержи 1 секунду. Пауза между разами 3 секунды. Когда закончишь — нажми «Готово»." --buttons "Готово,Не получается"
canhunt.py marks latest
```

`marks` печатает, какую долю записи покрывают окна у отметок (такую «точность» дал бы случайный бит), оценку с
поправкой на случайность и p. «Устойчивой реакции на отметки не найдено» — случайным совпадениям не верить.
`--window 2.0` — только для медленных реакций (например, свет гаснет через секунду).

**Эталон с прибора.** Точное значение по тахометру, спидометру или бортовому компьютеру пусть вводит пользователь:

```
car.py ask "Сколько сейчас на тахометре?" --input number --label "об/мин"
canhunt.py track latest --ref idle=800 --ref rpm2000=2000 --ref rpm1500=1500 --ref-inputs
```

Введённое число относится к фазе, которая активна в момент ввода (если фаз нет — к окну ±2 с вокруг ввода) и заменяет
её `--ref`. `--ref` и `--ref-inputs` сочетаются: одного ввода для `track` мало (нужно 2–3 уровня с эталоном), поэтому
остальные уровни задавай через `--ref`, или спрашивай число на каждом уровне — тогда хватит одного `--ref-inputs`.

**Что типично в кадрах:**
- счётчик 0..15 в младшей тетраде первого или последнего байта; контрольная сумма (XOR или CRC8) в последнем байте;
  у таких байтов высокая энтропия, и это не сигналы (их видно в `overview`);
- одна величина часто идёт в нескольких сообщениях: от ЭБУ-источника с периодом 10–20 мс и в копиях для приборки или
  шлюза с периодом 100–500 мс. Для прошивки лучше `le` (Intel), от источника и с коротким периодом;
- «нет данных» тоже бывает: 0xFF, 0xFFFF, 0x7FF… пока ЭБУ не готов, например сразу после включения зажигания;
- если по OBD кадров нет или только диагностика, в машине шлюз (gateway) и общий трафик на OBD не выходит.
  Нужно подключаться к шине напрямую (за приборкой, у блока). Комфортные сигналы (двери, свет, кнопки) часто на другой
  шине с другой скоростью (125/100/83.3 кбит/с) и через OBD их может не быть вовсе.

**Цепочка анализа** для любого сигнала:
`info` (фазы на месте?) → `compare`/`track`/`marks` (кандидаты) → `plot --field` (посмотреть PNG) →
`watch set` (живое значение) → `ask` «совпадает?» → `export` → запись в `CAN_HUNT/found/<машина>.md`.

## Передача (TX)

Сниффер умеет и **слать кадры в шину** (SPEC §11). Безопасность (подробно — SKILL §0, §10): передача пишет в
реальную шину, поэтому **только на стоянке, осознанно, по одному кандидату и с возвратом исходного состояния**. По
умолчанию канал молчит; писать можно лишь после явного перевода канала в активный режим. `car.py` сам канал в активный
режим не переводит — только по команде `active on`.

**Переслать кадр / периодическая отправка:**
```
car.py active on --ch 0 --br 125         # активный режим CAN0: канал начнёт ПИСАТЬ в шину (ACK + передача)
car.py tx 0 384 "01 FF 00"              # передать кадр ID 0x384 один раз (данные с пробелами — в кавычках)
car.py tx 0 10A AABB --period 100        # слать периодически каждые 100 мс (car.py tx-stop 1 — остановить)
car.py tx-list                           # какие слоты сейчас передаются и сколько кадров ушло
car.py tx-stop                           # остановить всю передачу
car.py active off --ch 0                 # вернуть канал в тихий режим
```

**Умный перебор (реверс команд).** Чтобы найти, каким кадром машина, например, запирает двери или зажигает лампу,
недостаточно слушать — нужно попробовать слать. Метод: возьми кадр, который **уже видел** в шине (из
`canhunt.py overview` или ленты монитора), и повтори его с изменёнными битами/байтами, глядя на реакцию (замок, свет,
приборка, звук):
1. Активируй нужный канал (`active on --ch N --br …` с известной скоростью шины).
2. Слей исходный кадр как есть (`tx N ID DATA`) — убедись, что он ничему не мешает.
3. Меняй по одному биту/байту (или перебирай значение поля-кандидата), после каждого варианта смотри реакцию машины и
   **возвращай исходное состояние**. Периодическую отправку (`--period`) используй, если команда действует только пока
   кадр повторяется; одиночную — если достаточно импульса.
4. Нашёл — запиши в `CAN_HUNT/found/<машина>.md` (ID, поле, что делает), останови слот (`tx-stop`) и верни канал в
   тихий режим (`active off`).

Правила перебора: по одному кандидату за раз, короткими сериями, между вариантами — исходное состояние; скорость шины
должна быть верной (иначе кадры уходят в ошибку); вслепую в шину неизвестного назначения не сыпать; на движущейся
машине передачу не вести. Если кадр «сломал» приборку или вызвал ошибку ЭБУ — обычно снимается зажиганием.

## Сужение через UDS (диагностика AUTEL)

Когда нужного параметра нет в «живой» шине (кодирование, скрытые опции, адаптации) — его чаще всего меняет тестер
через **диагностику** (UDS поверх ISO-TP). Шлюз при этом обходить не нужно: доступ к диагностике открывает сам AUTEL —
это часть его лицензии. Наша задача — не влезать в обмен, а **подсмотреть его сниффером** и разобрать, чтобы понять,
какой конфигурационный идентификатор (DID) отвечает за опцию. Это только чтение записи, активной отправки UDS нет.

Метод «сужения»:
1. **Записать обмен AUTEL.** Включи сниффер на диагностической шине (`car.py active off` — канал только слушает,
   молча) и `car.py session start autel_before`. Пусть AUTEL зайдёт в блок и покажет нужный экран (или прочитает
   кодирование). Останови запись.
2. **Найти блок и что тестер делал:**
   ```
   canhunt.py uds latest                    # блоки на шине, сервисы, сессии, прочитанные/записанные DID, лента ISO-TP
   canhunt.py uds latest --ecu 70 --service 22   # сузить: только блок 0x70 и чтения ReadDataByIdentifier
   ```
   В отчёте: пары адресов (запрос→ответ) с догадкой о роли, список DID с байтами ответа, записи 0x2E, routine 0x31,
   негативные ответы (7F … requestOutOfRange и т. п.). Типовые ID (0x7E0/0x7E8, 0x18DAxxyy) — только подсказка.
3. **Снять дамп конфигурации блока:**
   ```
   canhunt.py uds-did latest --ecu 70       # таблица всех DID блока и последних прочитанных байт
   ```
4. **Две записи «есть опция / нет опции» → кандидат в бит.** Запиши состояние с включённой функцией и с выключенной
   (или до/после переключения в AUTEL), затем сравни дампы:
   ```
   canhunt.py uds-diff есть.trc нет.trc --ecu 70
   ```
   `uds-diff` покажет, какой DID и какие именно байты/биты различаются — это и есть суженная область: дальше опция
   ищется уже не по всей шине, а в конкретном DID (и, если надо, точечно повторяется своим контроллером через TX, §11).

Файлы записи — как везде: папка сессии, `frames.log`, `.trc` (в т. ч. экспорт из AUTEL/PCAN) или `latest`.

## 1. Обороты двигателя

**Безопасность:** стоянка, P или нейтраль, ручник, никого вокруг. На холодном двигателе не выше 2000, на прогретом до 2500–3000 и коротко.

```
car.py session start rpm
car.py ask "Зажигание включено, двигатель пока НЕ заводи. Машина в P, ручник затянут? Если да — нажми «Готов»." --buttons "Готов=off,Не сейчас"
car.py ask "Подожди 5 секунд, нажми «Завожу» и сразу заводи двигатель." --buttons "Завожу=-,Не заводится"
car.py status                                         # после стартера: связь есть, сниффер ВКЛ, кадр/с > 0
car.py ask "Когда обороты стали ровными (секунд через 10), нажми «Холостые» и не трогай педали." --buttons "Холостые=idle"
car.py ask "Сколько точно на тахометре на холостых?" --input number --label "об/мин"
car.py ask "Держи холостые ещё 5 секунд и нажми «Дальше»." --buttons "Дальше=-"
car.py ask "Плавно подними обороты до 2000 (если двигатель прогрет — 2500) и держи. Когда стрелка встала — нажми «Держу»." --buttons "Держу=rpm2000,Двигатель холодный=-"
car.py ask "Сколько точно на тахометре?" --input number --label "об/мин"
car.py ask "Держи ещё 5 секунд, потом нажми «Отпускаю» и отпусти газ." --buttons "Отпускаю=-"
car.py ask "Теперь 1500 и держи. Когда стрелка встала — нажми «Держу 1500»." --buttons "Держу 1500=rpm1500,Не получается"
car.py ask "Держи 1500 ещё 5 секунд, потом нажми «Отпускаю» и отпусти газ." --buttons "Отпускаю=-"
```

`off` (двигатель стоит, зажигание включено) даёт точку «0». Порядок 2000 → 1500 (не по возрастанию) отделяет обороты
от таймеров. Повтори 1500 или 2000 ещё раз для надёжности.

**Анализ:**
```
canhunt.py info latest
canhunt.py track latest --ref off=0 --ref idle=800 --ref rpm2000=2000 --ref rpm1500=1500 --ref-inputs
canhunt.py plot latest --field "<SPEC кандидата>"
canhunt.py corr latest --field "<SPEC>"               # копии оборотов в других сообщениях
```
`--ref-inputs` берёт введённые числа (холостые, 2000) вместо `--ref` своих фаз; остальные уровни — из `--ref`.

**Чего ожидать:** 16 бит без знака; множитель ×0.25 (raw = об/мин×4, самый частый), ×0.125, ×0.5 или ×1, смещение 0.
Порядок бывает и `le`, и `be`. Иногда 14–15 бит, а в старших битах флаги. В сообщениях для приборки бывает грубая
копия: 8 бит ×25, ×32 или ×50. Период у ЭБУ двигателя 10–20 мс.
На холостых сигнал «дышит» ±20–50 об/мин. При `off` — 0 или «нет данных».

**Подтверждение:** `car.py watch set "Обороты=<SPEC>@об/мин"` → ask «Подними до 1500, потом 2500 (если прогрет). На экране
совпадает с тахометром?» `--buttons "Совпадает,Не совпадает"`. Допуск ±50 об/мин (стрелка тахометра инерционна).

## 2. Скорость автомобиля

**Безопасность:** только в движении, поэтому **только с пассажиром у ноутбука** (водитель ведёт, в экран не смотрит) или
запись без инструкций. Пустая площадка или тихая улица, скорость по правилам. Машину на домкрате не вывешивать.

С пассажиром:
```
car.py session start speed
car.py ask "Для ПАССАЖИРА. Машина стоит. Нажми «Стоим»." --buttons "Стоим=stop"
car.py ask "Водитель плавно разгоняется до 20 км/ч и держит. Когда спидометр встал на 20 — нажми «20»." --buttons "20=speed20,Не получается=-"
car.py ask "Сколько точно показывает спидометр?" --input number --label "км/ч"
car.py ask "Когда водитель разгоняется дальше — нажми «Разгон»." --buttons "Разгон=-"
car.py ask "Держим 40 км/ч, если безопасно. Когда встали на 40 — нажми «40»." --buttons "40=speed40,Нельзя=-"
car.py ask "Сколько точно показывает спидометр?" --input number --label "км/ч"
car.py ask "Остановитесь, где безопасно. Когда стоите — нажми «Стоим»." --buttons "Стоим=stop"
```
Вторая фаза `stop` в конце делает порядок эталонов немонотонным (0 → 20 → 40 → 0) — так таймеры отделяются от скорости.

Без пассажира: `car.py session start drive` → поездка 5–10 мин с разгонами, остановками и участками постоянной скорости →
`car.py session stop`. Потом спросить у пользователя, где ехал ровно и с какой скоростью. Анализ без фаз: `overview`
(поля, которые медленно меняются и равны 0 на остановках) и `plot --id`.

**Анализ:**
```
canhunt.py track latest --ref stop=0 --ref speed20=20 --ref speed40=40 --ref-inputs   # ввод уточняет 20 и 40
canhunt.py corr latest --field "<SPEC>"               # колёсные скорости и копии
```

**Чего ожидать:** 16 бит; ×0.01 км/ч (частое), 1/128 км/ч (0.0078125), ×0.1, ×0.05, ×1/256 (J1939, грузовики); у
американских машин бывают мили в час. Грубая копия 8 бит ×1 км/ч для приборки. Период 10–100 мс. **Спидометр завышает на
2–7 %**, поэтому подгонка даст, например, 0.0096 вместо 0.01. Бери «красивый» множитель, а точность проверяй по GPS
(навигатор или приложение).

**Подтверждение:** `watch set "Скорость=<SPEC>@км/ч"`. Пассажир сверяет с GPS и спидометром на 2–3 скоростях.

## 3. Педаль газа

**Безопасность:** зажигание включено, **двигатель НЕ заведён**. Тогда педаль можно выжимать до пола без риска.

```
car.py session start pedal
car.py ask "Зажигание включено, двигатель НЕ заводи. Ноги с педалей убери и нажми «Отпущена»." --buttons "Отпущена=pedal0"
car.py ask "Выжми газ на четверть хода и держи. Когда держишь ровно — нажми «Держу»." --buttons "Держу=pedal25,Не получается"
car.py ask "Держи ещё 5 секунд, затем нажми «Отпустил»." --buttons "Отпустил=-"
car.py ask "Теперь наполовину. Когда держишь ровно — нажми «Держу»." --buttons "Держу=pedal50"
car.py ask "Держи 5 секунд, затем нажми «Отпустил»." --buttons "Отпустил=-"
car.py ask "Теперь в пол. Когда держишь — нажми «Держу»." --buttons "Держу=pedal100"
car.py ask "Держи 5 секунд, затем нажми «Отпустил» и отпусти." --buttons "Отпустил=pedal0"
```

**Анализ:**
```
canhunt.py track latest --ref pedal0=0 --ref pedal25=25 --ref pedal50=50 --ref pedal100=100
canhunt.py compare latest --a pedal0 --b pedal100      # биты «педаль отпущена» и kickdown
```

**Чего ожидать:** 8 бит, 0..100 % как ×0.4 (0..250) или ×0.392 (0..255), бывает ×0.5; 10–12 бит ×0.1. Иногда
отпущенная педаль даёт ненулевой raw (смещение). Рядом часто бит «педаль отпущена» и kickdown. Положение дроссельной
заслонки — отдельное поле, и без работы двигателя оно почти не меняется. **Если при заглушённом двигателе ничего не
нашлось**, повтори на холостых, но только до ~25 % хода и коротко (обороты вырастут, см. §1).

**Подтверждение:** `watch set "Газ=<SPEC>@%"` → «Выжми наполовину, потом в пол. На экране 50 и 100?»

## 4. Тормоз: выключатель и давление

**Безопасность:** зажигание включено, двигатель не заведён, P и ручник. Без двигателя вакуумный усилитель после
2–3 нажатий «деревенеет». Это нормально, просто давить сильнее.

Выключатель (3 цикла):
```
car.py session start brake
car.py ask "Зажигание включено, двигатель не заводи. Ноги с педалей. Нажми «Отпущен»." --buttons "Отпущен=nobrake"
car.py ask "Нажми тормоз и держи. Когда держишь — нажми «Нажат»." --buttons "Нажат=brake"
car.py ask "Держи ещё 3 секунды и отпусти. Когда отпустил — нажми «Отпущен»." --buttons "Отпущен=nobrake"
```
Повторить пару «Нажат/Отпущен» ещё 2 раза.

Давление: фазы с разным усилием `brake_light`, `brake_mid`, `brake_hard` (пара «Держу/Отпустил» на каждую).

**Анализ:**
```
canhunt.py compare latest --a nobrake --b brake                                   # биты выключателя
canhunt.py track latest --ref nobrake=0 --ref brake_light=1 --ref brake_mid=2 --ref brake_hard=3   # монотонные поля давления
canhunt.py plot latest --field "<SPEC давления>"
```
Для давления эталона нет. Порядковые 0..3 дают только монотонных кандидатов, а масштаб берут из типичных значений.

**Чего ожидать:** выключатель — 1 бит; часто их два (основной и контрольный, логика друг к другу инвертирована), плюс
бит «стоп-сигнал включён» в сообщении кузовного блока. Давление — 8–16 бит от ESP/ABS, ×0.1 бар, ×0.01 бар или ×0.3 бар;
сильное нажатие без двигателя даёт десятки бар.

**Подтверждение:** `watch set "Тормоз=<SPEC бита>" "Давление=<SPEC>@бар"` → «Нажми и отпусти 3 раза: 1 и 0 на экране
совпадают?» Заодно можно проверить стоп-сигналы.

## 5. Селектор АКПП (P R N D)

**Безопасность:** ручник затянут, **нога на тормозе всё время**. Лучше при зажигании без двигателя: большинство машин
разрешает так выйти из P, двигатель не нужен. Если без двигателя не переключается — завести, ногу держать на тормозе,
после каждого положения возвращаться в P. В D и R педаль тормоза не отпускать.

```
car.py session start prnd
car.py ask "Ручник затянут, нога на тормозе. Селектор в P. Нажми «P»." --buttons "P=P"
car.py ask "Не отпуская тормоз, переведи в R. Когда стоит в R — нажми «R»." --buttons "R=R,Не переключается=-"
car.py ask "Переведи в N. Нажми «N»." --buttons "N=N"
car.py ask "Переведи в D. Нажми «D»." --buttons "D=D"
car.py ask "Обратно в N. Нажми «N»." --buttons "N=N"
car.py ask "В R. Нажми «R»." --buttons "R=R"
car.py ask "В P. Нажми «P»." --buttons "P=P"
```
Каждое положение держать 3–5 с до нажатия кнопки (фаза начинается с кнопки и идёт до следующей). Если есть M/S/L —
добавить их фазами. Одна инструкция — одна кнопка-фаза: `ask` возвращается на первом нажатии.

**Анализ:**
```
canhunt.py compare latest --a P --b R
canhunt.py compare latest --a P --b D
canhunt.py compare latest --a N --b D
canhunt.py decode latest --field "<SPEC поля селектора>"   # таблица «значение → положение»
```

**Чего ожидать:** перечисление в 3–4 битах. Коды у всех производителей разные, не угадывать: таблицу строить по
`decode`. Часто есть два поля: положение рычага (от селектора) и включённая передача (от коробки), плюс отдельный бит
заднего хода (фонари и парктроник). Копия для индикации на приборке.

**Подтверждение:** `watch set "Селектор=<SPEC>"` → «Пройди P-R-N-D: на экране меняется так же?» Записать таблицу значений в находки.

## 6. Стояночный тормоз

**Безопасность:** ровная площадка, АКПП в P (механика — на передаче), нога на тормозе при отпускании. Зажигание
включено, двигатель не нужен (для электронного ручника иногда нужен запуск: тогда P и нога на тормозе).

```
car.py session start pbrake
car.py ask "Нога на тормозе, ручник затянут. Нажми «Затянут»." --buttons "Затянут=pb_on"
car.py ask "Не отпуская тормоз, отпусти ручник. Когда отпущен — нажми «Отпущен»." --buttons "Отпущен=pb_off"
car.py ask "Снова затяни ручник. Когда затянут — нажми «Затянут»." --buttons "Затянут=pb_on"
```
3 цикла.

**Анализ:** `canhunt.py compare latest --a pb_off --b pb_on`

**Чего ожидать:** механический ручник даёт 1 бит концевика в сообщении кузовного блока или приборки. Электронный (EPB)
даёт статус в 2–3 битах (отпущен / затягивается / затянут / отпускается / ошибка) и отдельно кнопку. Для EPB поставь
отметку на момент нажатия кнопки и смотри переходные состояния в `plot`.

**Подтверждение:** `watch set "Ручник=<SPEC>"`, 2 цикла, сверка с лампой на приборке.

## 7. Задний ход

АКПП — берётся из §5 (бит R или код R в поле селектора). Механика: зажигание включено, **двигатель не заведён**, сцепление
выжато, ручник:

```
car.py session start reverse
car.py ask "Двигатель не заводи. Выжми сцепление, рычаг в нейтраль. Нажми «Нейтраль»." --buttons "Нейтраль=N"
car.py ask "Включи заднюю. Когда включена — нажми «Задняя»." --buttons "Задняя=R"
car.py ask "Обратно в нейтраль. Нажми «Нейтраль»." --buttons "Нейтраль=N"
```
3 цикла. **Анализ:** `canhunt.py compare latest --a N --b R`.
**Чего ожидать:** 1 бит (концевик фонаря заднего хода) в сообщении ЭБУ двигателя или кузовного блока, иногда и
«фонари заднего хода включены». **Подтверждение:** `watch` плюс фонари заднего хода (попросить глянуть в зеркало или камеру).

## 8. Угол поворота руля

**Безопасность:** машина стоит, P и ручник. С ГУР или ЭУР руль лёгкий при работающем двигателе, но датчик угла обычно
работает и от одного зажигания. **В крайнем положении не держать дольше 5 с.**

```
car.py session start steer
car.py ask "Поставь руль прямо (колёса прямо). Когда стоит — нажми «Прямо»." --buttons "Прямо=center"
car.py ask "Поверни руль на четверть оборота ВЛЕВО (90°) и держи. Нажми «Держу»." --buttons "Держу=left90"
car.py ask "Верни прямо и нажми «Прямо»." --buttons "Прямо=center"
car.py ask "Поверни на четверть оборота ВПРАВО (90°) и держи. Нажми «Держу»." --buttons "Держу=right90"
car.py ask "Верни прямо и нажми «Прямо»." --buttons "Прямо=center"
car.py ask "Пол-оборота ВЛЕВО (180°), держи. Нажми «Держу»." --buttons "Держу=left180"
car.py ask "Верни прямо и нажми «Прямо»." --buttons "Прямо=center"
```

**Анализ:**
```
canhunt.py track latest --ref center=0 --ref left90=90 --ref right90=-90 --ref left180=180
canhunt.py compare latest --a left90 --b right90         # бит знака, если кодировка «знак + модуль»
```
Если линейного кандидата со знаком нет, попробуй модуль: `--ref center=0 --ref left90=90 --ref right90=90 --ref left180=180`
(для `track` нужно минимум 3 разных эталона). Это найдёт поле величины,
а знак даст отдельный бит из `compare`.

**Чего ожидать:** 15–16 бит; дополнительный код ×0.1°, ×0.0625° или ×0.04375°; бывает «знак + модуль». Влево обычно
«+», но не всегда. Рядом скорость вращения руля, счётчик и CRC (у датчика угла почти всегда). Центр может быть не
ровно 0 (калибровка).

**Подтверждение:** `watch set "Руль=<SPEC>@°"` → «Поверни на полный оборот влево: на экране около 360?»

## 9. Поворотники и аварийка

**Безопасность:** зажигание включено, двигатель не нужен.

```
car.py session start turn
car.py ask "Все поворотники выключены. Нажми «Выкл»." --buttons "Выкл=off"
car.py ask "Включи ЛЕВЫЙ поворотник. Через 5 секунд нажми «Левый»." --buttons "Левый=left"
car.py ask "Выключи, подожди 3 секунды, нажми «Выкл»." --buttons "Выкл=off"
car.py ask "Включи ПРАВЫЙ. Через 5 секунд нажми «Правый»." --buttons "Правый=right"
car.py ask "Выключи, нажми «Выкл»." --buttons "Выкл=off"
car.py ask "Включи АВАРИЙКУ. Через 5 секунд нажми «Аварийка»." --buttons "Аварийка=hazard"
car.py ask "Выключи, нажми «Выкл»." --buttons "Выкл=off"
```

**Анализ:**
```
canhunt.py compare latest --a off --b left
canhunt.py compare latest --a off --b right
canhunt.py compare latest --a off --b hazard
canhunt.py plot latest --id <CH:ID кандидата>            # мигающие биты видны «гребёнкой»
canhunt.py decode latest --field "<SPEC бита>"          # доля единиц по фазам
```

**Чего ожидать:** два вида битов. Постоянные «запрос» (положение подрулевого переключателя) хорошо ловятся `compare`.
Мигающие «лампа горит» (~1.5 Гц) внутри фазы нестабильны, поэтому `compare` их может пропустить: ищи в `plot --id`
или по доле единиц около 0.5 в `decode`. Аварийка — оба мигающих бита плюс отдельный бит кнопки.

**Подтверждение:** `watch set "Левый=<SPEC>" "Правый=<SPEC>"` → включить левый, правый, аварийку.

## 10. Свет: габариты, ближний, дальний

**Безопасность:** зажигание включено, двигатель не заводить. Долго со светом не стоять: аккумулятор. Автосвет выключить
(ручной режим).

```
car.py session start lights
car.py ask "Переключатель света в положение «выкл» (не «авто»). Нажми «Выкл»." --buttons "Выкл=off"
car.py ask "Включи ГАБАРИТЫ. Через 5 секунд нажми «Габариты»." --buttons "Габариты=side"
car.py ask "Включи БЛИЖНИЙ. Через 5 секунд нажми «Ближний»." --buttons "Ближний=low"
car.py ask "Включи ДАЛЬНИЙ (рычаг от себя). Через 5 секунд нажми «Дальний»." --buttons "Дальний=high"
car.py ask "Выключи дальний, потом весь свет. Нажми «Выкл»." --buttons "Выкл=off"
```
Повторить цикл ещё раз. «Моргнуть дальним» — через отметки (сначала «Отметка», потом рычаг на себя на 1 с, 3 раза).

**Анализ:** `compare --a off --b side`, `--a side --b low`, `--a low --b high`; моргание — `marks`.
**Чего ожидать:** биты в сообщении кузовного блока или подрулевого модуля: положение переключателя (часто 2–3 бита
перечислением) и отдельно «лампа включена». Индикатор дальнего есть и в сообщении приборки.
**Подтверждение:** `watch` на 2–3 бита, пройти положения ещё раз.

## 11. Двери, багажник, капот

**Безопасность:** капот открывать только при заглушённом двигателе. На дороге двери не открывать (только на стоянке, со
стороны тротуара).

Отметками (быстро, по каждой двери):
```
car.py session start doors
car.py ask "Все двери закрыты. 3 раза: нажми «Отметка — сейчас!», сразу открой ВОДИТЕЛЬСКУЮ дверь; подожди 3 секунды; нажми «Отметка» и сразу закрой. Когда закончишь — нажми «Готово»." --buttons "Готово,Не получается"
canhunt.py marks latest
```
Или фазами: `closed` / `door_fl` (открыта) по 5 с, 3 цикла → `compare --a closed --b door_fl`. Потом так же
остальные двери (`door_fr`, `door_rl`, `door_rr`), багажник (`trunk`), капот (`hood`).

**Чего ожидать:** по биту на дверь, обычно все двери в одном байте сообщения кузовного блока, багажник и капот рядом.
Сигналы комфорта часто живут на отдельной низкоскоростной шине (83.3–125 кбит/с) и через OBD могут не выходить.
Если ничего не нашлось, спроси, к какой шине подключён контроллер.
**Подтверждение:** `watch set` на найденные биты → «Открой и закрой каждую дверь по очереди».

## 12. Замки (центральный замок)

**Безопасность и удобство:** ключ держать в руке, окно водителя открыть: не захлопнуть ключ в машине и не поставить на
охрану с датчиками объёма (сработает сирена). Запирать кнопкой в салоне, если она есть.

```
car.py session start locks
car.py ask "3 раза: нажми «Отметка — сейчас!» и сразу ЗАПРИ кнопкой в салоне; подожди 3 секунды; «Отметка» и сразу ОТОПРИ. Потом нажми «Готово»." --buttons "Готово,Не получается"
canhunt.py marks latest
```
Фазами: `unlocked` / `locked` → `compare`.
**Чего ожидать:** статус «заперто» (1 бит или по биту на дверь), отдельно события команды (кнопка или брелок) —
короткие импульсы и счётчики. Статус «заперто» подходит для прошивки, событие — для реакции на нажатие.
**Подтверждение:** `watch` на бит статуса, запереть и отпереть 2 раза.

## 13. Кнопки на руле

**Безопасность:** зажигание включено (или ACC), двигатель не нужен, машина стоит.

По одной кнопке за шаг, отметками:
```
car.py session start wheel_buttons
car.py ask "Кнопка «Громкость +». 5 раз: нажми «Отметка — сейчас!», сразу нажми на руле «+» и подержи 1 секунду. Пауза 3 секунды. Потом нажми «Готово»." --buttons "Готово=-,Нет такой кнопки"
canhunt.py marks latest
```
Так же для остальных кнопок. Чтобы разделить кнопки в анализе, перед каждой начинай фазу (`car.py phase btn_volup`,
затем `phase -`) и смотри `canhunt.py marks latest --phase btn_volup`: берутся только отметки этой фазы, и «вне окон»
считается тоже только в ней (нажатия других кнопок не мешают). Или делай отдельную сессию на каждую кнопку.

**Чего ожидать:** чаще перечисление в одном байте (0 — ничего не нажато, у каждой кнопки свой код), реже по биту на
кнопку. Кнопки часто идут по LIN в модуль под рулём, а в CAN попадают через него или через шлюз, с периодом 20–100 мс.
Некоторые кнопки (круиз, телефон) могут быть в разных сообщениях. Колёсико прокрутки даёт счётчик.
**Подтверждение:** `watch set "Кнопки=<SPEC>"` → «Нажимай кнопки по очереди»; составь таблицу «код → кнопка».

## 14. Положения ключа (OFF / ACC / ON / START)

car.py session start key

car.py ask "Положение ACC (аксессуары, без зажигания). Через 5 секунд нажми «ACC»." --buttons "ACC=acc,Нет ACC=-"

## 15. Температура охлаждающей жидкости

Меняется медленно, поэтому нужен прогрев от холодного двигателя. **Безопасность:** на улице (не в закрытом гараже),
P, ручник, холостые, без перегазовок.

```
car.py session start coolant
car.py ask "Двигатель холодный? Заведи и оставь на холостых. Сколько °C показывает бортовой компьютер (или сканер OBD)?" --input number --label "°C"
```
Дальше каждые 3–4 минуты тот же `ask` с `--input number` (15–20 мин прогрева, 5–6 точек). Если в машине нет
показаний в °C, пусть пользователь вводит положение стрелки (деления), а масштаб подбираем по типичным кодировкам.

**Анализ:**
```
canhunt.py track latest --ref-inputs              # ввод без фаз относится к окну ±2 с
canhunt.py overview latest                        # байты-«сигналы» с медленным ростом
canhunt.py plot latest --field "<SPEC>"
```

**Чего ожидать:** 8 бит, **°C = raw − 40** (самое частое), бывает ×0.75 − 48, 16 бит ×0.1 − 40 или ×0.01 − 40.
Температура растёт быстро, потом держится на 85–100 °C (термостат). Рядом похожие поля: масло (растёт медленнее),
воздух на впуске, наружная температура. Не путать. Стрелка на приборке нелинейна: в середине шкалы у неё «плато».
**Подтверждение:** `watch set "ОЖ=<SPEC>@°C"`, сверка с бортовым компьютером или сканером в двух точках.

## 16. Уровень топлива

Меняется только при заправке. **Безопасность:** на АЗС двигатель заглушен, ноутбук не мешает заправке, сессию не
останавливать.

```
car.py session start fuel
car.py ask "Зажигание включено, двигатель можно не заводить. Нажми «Начали»." --buttons "Начали=fuel_before"
car.py ask "Сколько топлива показывает прибор или бортовой компьютер (литры или доля бака)?" --input number --label "л или %"
```
Минута записи → `car.py phase -` → зажигание выключить → заправка → зажигание включить, подождать 1–2 мин (указатель
сглажен) → те же два `ask` с фазой `fuel_after`. Лучше разница в полбака и больше.

**Анализ:** `canhunt.py compare latest --a fuel_before --b fuel_after` и `decode latest --field SPEC` по фазам.
`track` требует минимум 3 разных эталона, поэтому по двум точкам масштаб берём из типичных кодировок (ниже) и
проверяем на следующей заправке (новая сессия, `decode --field` на ней).
**Чего ожидать:** 8 бит в % (×0.4 или ×1) или в литрах (×0.5 или ×1); бывает сырое сопротивление датчика (нелинейно) и
отдельно отфильтрованное значение для приборки; бит «мало топлива». Часто только в сообщениях приборки.
**Подтверждение:** сверка со стрелкой и бортовым компьютером на следующей заправке.

## 17. Скорости колёс

**Безопасность:** только в движении, только **с пассажиром у ноутбука** или записью без инструкций; пустая площадка,
10–20 км/ч.

```
car.py session start wheels
car.py ask "Для ПАССАЖИРА. Стоим — нажми «Стоим»." --buttons "Стоим=stop"
car.py ask "Едем прямо 10 км/ч. Когда ровно — нажми «10»." --buttons "10=straight10,Нельзя=-"
car.py ask "Прямо 20 км/ч. Когда ровно — нажми «20»." --buttons "20=straight20,Нельзя=-"
car.py ask "Сколько на спидометре?" --input number --label "км/ч"
car.py ask "Медленный круг ВЛЕВО (руль заметно влево, 10 км/ч). Когда едем по кругу — нажми «Влево»." --buttons "Влево=circle_left,Нельзя=-"
car.py ask "Медленный круг ВПРАВО. Когда едем по кругу — нажми «Вправо»." --buttons "Вправо=circle_right,Нельзя=-"
car.py ask "Остановитесь. Нажми «Стоим»." --buttons "Стоим=stop"
```

**Анализ:**
```
canhunt.py track latest --ref stop=0 --ref straight10=10 --ref straight20=20   # 4 кандидата с одинаковым множителем
canhunt.py compare latest --a circle_left --b circle_right     # какие колёса внешние
canhunt.py plot latest --field "<SPEC1>" --field "<SPEC2>" --field "<SPEC3>" --field "<SPEC4>"
```
В повороте внешние колёса быстрее внутренних, передние быстрее задних (у передних радиус больше). Так определяется
каждое колесо.

**Чего ожидать:** 4 поля по 12–16 бит, обычно в одном сообщении ABS/ESP с периодом 10–20 мс, ×0.01 км/ч, 1/128 км/ч,
×0.0625 или ×0.05; иногда в старших битах направление вращения. Отдельно бывают счётчики импульсов (зубьев) колёс:
растут только в движении и переполняются. На стоянке всё равно 0.
**Подтверждение:** `watch` на 4 поля, прямой участок (все примерно равны и близки к скорости) и поворот (внешние больше).

## Если ничего не нашлось

1. `canhunt.py info latest`: фазы записаны? кадры есть на всех нужных каналах?
2. `car.py status`: все ли каналы слушаются (`sniff on`), нет ли потерь (drop/lost)?
3. Сигнал может быть только в другой шине (комфорт, мультимедиа, шасси) или отдаваться только по диагностическому
   запросу (UDS/OBD). Сниффер видит только общий трафик: скажи пользователю честно, какую шину стоит попробовать.
4. Повтори эксперимент с большим контрастом: дольше фазы, больше уровней, 5 повторов вместо 3.
