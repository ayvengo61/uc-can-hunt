# CAN_HUNT: совместный поиск сигналов в CAN

Пользователь сидит в машине. Перед ним ноутбук со страницей монитора `/assist`: там крупно видна текущая инструкция, есть кнопки,
«Отметка — сейчас!», «Сообщение для Claude» и живые значения полей из наблюдения. Claude работает в Claude Code на этом же ноутбуке.
Он даёт **одну короткую инструкцию за раз**, ждёт нажатия кнопки, анализирует запись и подтверждает находку живым значением.

Контракт системы (формат поля, события, API): `${CLAUDE_SKILL_DIR}/SPEC.md`.
Сценарии по сигналам (готовые команды, кодировки, анализ): `${CLAUDE_SKILL_DIR}/PLAYBOOK.md`.
**Перед каждым экспериментом прочитай нужный раздел PLAYBOOK.**

## Инструменты (путь — через ${CLAUDE_SKILL_DIR}, всегда в кавычках: в пути могут быть пробелы)

Папка навыка: `${CLAUDE_SKILL_DIR}`. Мониторы плат лежат в пакете плагина: `${CLAUDE_SKILL_DIR}/../../monitor/<плата>/`.
Нужны Python 3 с пакетами numpy и pillow (`pip install numpy pillow`) и Windows (монитор — exe на .NET Framework 4.x).
Записи сессий монитор кладёт в `can_sessions` рядом со своим exe; canhunt.py ищет их там сам (или в папках из
переменной CANHUNT_SESSIONS). Находки записывай в проект пользователя: `${CLAUDE_PROJECT_DIR}/can_hunt_found/`.

```
python "${CLAUDE_SKILL_DIR}/scripts/car.py" <команда>       # команды монитору
python "${CLAUDE_SKILL_DIR}/scripts/canhunt.py" <команда> <вход> [опции]  # анализ записей
```

Ниже для краткости: `car.py …` и `canhunt.py …`, но в Bash всегда пиши полную команду выше: переменные окружения между
вызовами Bash не сохраняются. Прямые слэши в пути работают и в Git Bash, и в PowerShell. Если синтаксис canhunt.py
расходится с этим текстом, сверься с `canhunt.py <команда> --help`.

Коды выхода car.py: 0 — успешно или событие пришло; 1 — монитор недоступен; 2 — таймаут ожидания; 3 — ошибка (аргументы,
ok:false, старый монитор, контроллер не подключён, канал сниффера не «молча»); 4 — пользователь прислал сообщение вместо
ответа (у `ask` и `wait --say`); 5 — инструкцию заменили новой (`ask`/`wait --say`, ожидание снято); 6 — пропала связь с
контроллером или выключился сниффер — кадры не пишутся (`ask`/`wait`).

## 0. Безопасность (строго, важнее результата)

- **Двигатель и обороты — только на стоянке**: АКПП в P (механика — нейтраль), затянут стояночный тормоз, никого нет
  перед машиной и за ней. В закрытом гараже двигатель долго не держать.
- **Водителю в движении ничего не поручать.** Скорость, колёсные скорости и всё, что требует езды, делаются так:
  1) за ноутбуком сидит пассажир, водитель только ведёт машину; либо 2) пишем поездку целиком (`session start` → поездка →
  `session stop`) и разбираем запись потом. Инструкции для поездки дают только пассажиру и только там, где безопасно
  (пустая площадка, низкая скорость, правила движения важнее эксперимента).
- **Руль — только на месте.** В крайнем положении не держать дольше 5 секунд (насос ГУР).
- **Холодный двигатель — без высоких оборотов.** До прогрева не выше ~2000 об/мин. Если нужно 3000 и выше, то только на
  прогретом двигателе и коротко (5–10 с). Обычно хватает 2–3 уровней, до 2500.
- Где можно, сигнал ищем при включённом зажигании **без запуска двигателя**: педаль газа, тормоз, свет, двери, ручник,
  часто и селектор (нога на тормозе).
- Селектор PRND переключать только с ногой на тормозе, ручник затянут. Если двигатель работает, после каждого положения
  возвращать P.
- Капот открывать и закрывать только при заглушенном двигателе. Не просить лезть в моторный отсек при работающем двигателе.
- Сниффер прошивки слушает «молча» (Bus Monitoring: без ACK, кадров ошибок и передачи). Это проверяется, а не
  предполагается: `car.py status` пишет у каждого включённого канала «молча». Если канал «НЕ молча» (старая прошивка:
  канал, включённый в конфиге в режиме Normal, остаётся Normal — подтверждает кадры и шлёт в шину кадры своего
  конфига; на шине с другой скоростью он засыпал бы её кадрами ошибок), сразу `car.py sniff off --ch N`, дальше —
  прошить свежую прошивку со сниффером или выключить этот канал в конфиге, пока шина машины неизвестна.
- **Передача (TX) — только осознанно и только на стоянке.** По умолчанию канал слушает молча и в шину ничего не
  пишет. Писать можно лишь после явного `car.py active on --ch N` — это переводит канал в активный режим (Normal):
  контроллер начинает подтверждать кадры (ACK) и передавать. Включай активный режим и шли кадры только когда это
  действительно нужно (проверить гипотезу о команде, «оживить» узел), на стоянке, по одному кандидату, и сразу
  возвращай канал в тихий режим: `car.py active off`. Не переводи канал в активный «на всякий случай» и не оставляй
  передачу висеть. Скорость шины должна быть известна и правильна (`--br`): передача на чужой скорости сыплет в шину
  ошибки. Периодическая передача сама останавливается, если контроллер теряет ноутбук (защита прошивки), но всё равно
  останавливай слоты сам (`car.py tx-stop`). Подробно — §10.
- Аккумулятор: при зажигании без двигателя дольше ~15–20 минут (несколько сигналов подряд) сделай паузу —
  попроси выключить зажигание на пару минут или прогреть двигатель на холостых (если это безопасно и уместно).
  Пока сниффер включён, контроллер не засыпает и держит шину: после эксперимента `car.py sniff off`.
- Если пользователь пишет, что что-то не так (запах, ошибки на приборке, машина покатилась), сразу останавливаемся:
  `car.py phase -`, затем инструкция «Заглуши двигатель / поставь P и ручник», дальше выясняем, что случилось.

## 1. Предпосылки (проверить до начала)

1. Контроллер прошит версией **со сниффером** (`app/can_sniff.c`), подключён к CAN машины и по USB к ноутбуку.
2. Запущен монитор (пользователь запускает сам, кнопка «Совместная работа» открывает `/assist`):
   - G4: `${CLAUDE_SKILL_DIR}/../../monitor/G4/UC_G4_Monitor.exe`, порт 8473;
   - H723: `${CLAUDE_SKILL_DIR}/../../monitor/H723/UC_H723_Monitor.exe`, порт 8723;
   - H503: `${CLAUDE_SKILL_DIR}/../../monitor/H503/UC_H503_Monitor.exe`, порт 8503 (одна шина — канал 0).
3. `car.py status` показывает плату и порт (`Монитор UC_G4: http://127.0.0.1:8473`), связь с контроллером, сниффер по
   каналам (скорость, «молча», кадр/с), сессию и фазу, а в последней строке «Готово к работе.» или «НЕ ГОТОВО: …» с причиной.
   - Порт car.py находит сам (8473 → 8723 → 8503, а также порт из `%TEMP%\UC_<плата>_Monitor[_demo].port`, если
     стандартный был занят и монитор взял +1…+9) и запоминает. Если запущено несколько мониторов, укажи `--port N`.
   - Демо без машины: пользователь запускает exe с `--demo`, порт 18473/18723/18503 → один раз `car.py --port 18473 status`,
     дальше car.py помнит этот порт. В демо `sniff on/off` выполняет демо-машина.
4. Сниффер выключен → `car.py sniff on` (все каналы, скорость из конфига) или `car.py sniff on --ch 0 --br 500`
   (`--fd 1 --dbr 2000` для CAN FD). Код 3 и «НЕ ГОТОВО: … не в режиме «молча»» → см. §0 (сразу `sniff off`).
   Кадров 0 при включённом канале — значит, не включено зажигание, не та скорость шины
   (пробуй 500, потом 250, 125, 1000) или не то подключение CAN-H/CAN-L. Попроси пользователя включить зажигание.
5. «потери кадров drop/lost» → поток больше, чем пропускает USB: слушать только нужный канал (`sniff off --ch 1` и т. п.).
6. Спроси марку, модель и год (`ask … --input text`): они нужны для файла находок.

## 2. Старт

```
car.py sniff on
car.py session start rpm              # одна сессия на один искомый сигнал; имя латиницей: rpm, speed, brake, doors…
car.py ask "Нажми жёлтую плашку «Звук выключен» вверху страницы, чтобы слышать новые инструкции. Потом нажми «Готово»."
car.py ask "Проверим безопасность: машина на стоянке, P и ручник? Когда да — нажми «Готов»." --buttons "Готов,Не сейчас"
```

Запись идёт в `<папка exe>\can_sessions\<дата>_<имя>\` (frames.log + events.jsonl + meta.json). Путь печатает `car.py session`.
`session start` предупреждает, если сниффер выключен (кадры не пишутся) и если уже идёт фаза (она попадёт в запись с
начала) — в этих случаях сначала `car.py sniff on` / `car.py phase -`.

## 3. Цикл эксперимента

**Всегда слушай страницу.** Сообщение и кнопки со страницы доходят до Claude, только пока висит `ask`/`wait` в фоне —
иначе ничто его не разбудит. Поэтому, пока идёт работа, в каждый момент должно быть запущено одно из: `ask`, цепочка
`ask_chain.py` или (пока анализируешь/думаешь) `car.py wait --types note,mark --timeout 1800` в фоне; после пробуждения —
сразу перезапусти. Страница показывает пользователю «● Claude на связи» или «не слушает — напишите в чат Claude Code».
(19.09.2026 пользователь написал на странице, а ответа не было: ожидание не было запущено.)

**Цепочка инструкций** — когда шаги известны заранее (циклы вкл/выкл, уровни): файл по строке на шаг
`ТЕКСТ || КНОПКИ` и одна фоновая команда
`python "${CLAUDE_SKILL_DIR}/scripts/ask_chain.py" steps.txt` — Claude просыпается один раз в
конце или раньше, если пользователь написал сообщение (код 4), пропала связь (6) и т.п. Шаги можно писать в scratch.

**Кнопки с запятой в надписи** («Темно, я один») ломают разбор — разделяй кнопки `|`:
`--buttons "Темно и с пассажиром|Темно, я один|Светло"` (или `\,` внутри надписи).

1. **Одна инструкция за раз** через `ask`, **запущенный в фоне**: инструмент Bash с `run_in_background: true`.
   Claude получит уведомление, когда пользователь нажмёт кнопку. **Не опрашивай в цикле** и не запускай `sleep`.
   Пока ждёшь, можно анализировать уже записанное.
   ```
   python "${CLAUDE_SKILL_DIR}/scripts/car.py" ask "Подними обороты до 2000 и держи. Когда стрелка встала на 2000 — нажми «Держу 2000»." --buttons "Держу 2000=rpm2000,Не получается=-"
   ```
   Когда пришло уведомление, прочитай вывод: там ответ (`Ответ: кнопка «Держу 2000», фаза «rpm2000» началась`),
   отметки и сообщения пользователя, пришедшие по пути, и строки «ВНИМАНИЕ: нажата кнопка «…» инструкции #N (не
   текущей) → …» — пользователь нажал кнопку старой инструкции, фаза могла смениться (в конце: «сейчас фаза: …»);
   тогда поправь фазы (`car.py phase …` / `phase -`) и, если отрезок испорчен, повтори шаг.
   - код 0 — ответ пришёл, идём дальше;
   - код 4 — пользователь написал сообщение (текст в выводе). Ответь новой инструкцией (она заменит текущую) или, если
     инструкция ещё в силе, жди её дальше: `car.py wait --say N` в фоне;
   - код 5 — ты сам выдал новую инструкцию, эта снята: ничего делать не нужно (жди ответ на новую);
   - код 6 — пропала связь с контроллером или выключился сниффер, кадры не пишутся: см. §9;
   - код 2 — за 15 мин ответа нет: спроси в чате «Ты здесь?» (новая инструкция через `ask` заменит текущую —
     делай так, только если текущая уже не нужна);
   - код 1 — монитор недоступен, см. §9.
2. **Фазы — через кнопки.** В `--buttons "Надпись=фаза,…"`: `=имя` начинает фазу, `=-` заканчивает, без `=` фазу не трогает.
   Фаза — отрезок записи, с которым потом работает анализ. Имена латиницей без пробелов: `idle`, `rpm1500`, `off`,
   `brake`, `P`, `R`, `N`, `D`, `left`, `right`, `hazard`, `low`, `high`, `door_fl`.
   Типовая пара кнопок: начать фазу в момент, когда состояние установилось, и закончить её перед следующим действием.
   Закрыть фазу вручную: `car.py phase -`.
3. **Числовой сигнал** (обороты, педаль, давление, угол): 3–4 уровня плюс «ноль», каждый держать 5–10 с стабильно,
   **не по возрастанию** (например idle → 2500 → 1500 → 2000): при фазах строго по возрастанию таймер или счётчик
   неотличим от сигнала. Точное значение по прибору пусть вводит пользователь: `--input number --label "об/мин по
   тахометру"`. Потом `track --ref …` для всех уровней; `--ref-inputs` можно добавить к `--ref` — введённое число
   уточнит свою фазу (одного ввода мало: для `track` нужно хотя бы 2–3 уровня с эталоном).
4. **Кнопки и переключатели:** «нажми N раз (5 и больше), после каждого нажатия жми «Отметка — сейчас!»», дальше
   анализ через `marks` (сдвиг окна он подбирает сам: неважно, жмут отметку до действия или после). Несколько кнопок в
   одной записи — перед каждой своя фаза (`car.py phase btn_volup`, потом `phase -`) и `marks --phase btn_volup`.
   Или фазы вкл/выкл по 5 с, дальше `compare`.
5. Инструкцию, которую не нужно ждать (например «Глуши двигатель, спасибо»), давай через `car.py say`.
6. Свои пометки в журнал: `car.py note "Смотрю запись, минуту"` (пользователь видит их на странице), `car.py mark "…"`.

## 4. Анализ (canhunt.py)

Вход — папка сессии (её печатает `car.py session`; frames.log сбрасывается на диск раз в секунду, поэтому идущую сессию
тоже можно разбирать) или `latest` (последняя сессия монитора: сначала того, с которым последним работал car.py, в том
числе демо на 18473, потом 8473/8723/8503). Если запущено несколько мониторов, надёжнее передать папку из `car.py session`.

```
canhunt.py info latest                                  # длительность, кадры (и в каждой фазе), ID, фазы, отметки, ввод
canhunt.py overview latest --ch 0                       # по ID: частота, какие байты константы/счётчики/CRC/сигналы
canhunt.py compare latest --a idle --b rpm2000          # что отличает состояния (биты и поля 8/16)
canhunt.py track latest --ref idle=800 --ref rpm2500=2500 --ref rpm1500=1500   # линейная связь с эталоном → spec
canhunt.py track latest --ref idle=800 --ref rpm2500=2500 --ref rpm1500=1500 --ref-inputs   # + числа с прибора
canhunt.py marks latest                                 # что меняется у каждой отметки (сдвиг окна подбирается)
canhunt.py marks latest --phase btn_volup               # только отметки внутри фазы btn_volup
canhunt.py corr latest --field "0:0C9:1.7:16:be*0.25"   # другие поля, коррелирующие с найденным (копии сигнала)
canhunt.py decode latest --field SPEC                   # статистика поля по фазам
canhunt.py plot latest --field SPEC [--field SPEC2]     # PNG: время, закрашенные фазы, отметки
canhunt.py plot latest --id 0:0C9                       # «тепловая полоса» всех байтов ID
canhunt.py export latest --field SPEC --name rpm        # строка для прошивки + DBC SG_
```

- Графики **смотри сам**: `plot` печатает путь к PNG, открой его инструментом Read и проверь, что поле ступенями
  повторяет фазы, без скачков и переполнений.
- Кандидатов обычно несколько (одна величина в нескольких сообщениях, от ЭБУ двигателя и от приборки). Для прошивки
  предпочитай поле `le` (прошивка читает только Intel), с частым периодом и от источника сигнала.
- Счётчики и CRC — не сигналы. Если кандидат прыгает в каждом кадре, это не он.
- Не делай выводов по одной фазе. Для числа нужны минимум 3 уровня, для бита — минимум 3 переключения.
- Читай пометки `track`: «(слабое совпадение)» — оценка < 0.5; «похоже на таймер» — растёт со временем и внутри фаз;
  «* — в начале фазы значение ещё менялось» — уровень смещён переходным процессом (смещение OFFSET может уйти на шаг
  округления); «граница поля неоднозначна» — те же значения даёт и другая длина (лишние биты в записи не менялись);
  «варианты той же области» — с масштабом и СКО подгонки. При трёх уровнях у подгонки одна степень свободы — находку
  обязательно подтверждай живым значением (§5).
- `marks`: смотри «Окна покрывают N %» (такую точность дал бы случайный бит), оценку и p. «Устойчивой реакции на
  отметки не найдено» — значит, случайным совпадениям не верить: повтори действие 5+ раз или проверь шину.
- `info` и анализ предупреждают о фазах без кадров и паузах в кадрах — такие фазы в анализе не участвуют; запись без
  кадров анализ отвергает (код 1): включи сниффер и запиши заново.

**Диагностика (UDS) — когда сигнала в живой шине нет.** Скрытые опции, кодирование и адаптации меняются не «живым»
кадром, а через диагностику. Записав сниффером обмен AUTEL с блоком (шлюз обходить не нужно — доступ даёт сам AUTEL),
разбери его (только чтение):

```
canhunt.py uds latest                    # блоки (пары адресов), сервисы, сессии, прочитанные/записанные DID, лента ISO-TP
canhunt.py uds latest --ecu 70 --service 22   # сузить: только блок 0x70 и чтения ReadDataByIdentifier
canhunt.py uds-did latest --ecu 70       # дамп всех DID блока и последних байт (конфигурация)
canhunt.py uds-diff есть.trc нет.trc --ecu 70   # что отличается между «опция вкл/выкл» → DID и биты-кандидаты
```

Применяй, когда пользователь говорит про кодирование, скрытую функцию, «прописать/включить опцию», адаптацию, дамп
блока, «разбери лог сканера/AUTEL», или когда сигнал не находится в шине, но заведомо управляется диагностикой. Типовые
ID в отчёте (0x7E0/0x7E8, 0x18DAxxyy) — только подсказка. Активной отправки UDS нет; если найденное надо повторить —
точечно через TX (§10). Подробный сценарий — «Сужение через UDS» в `PLAYBOOK.md`.

## 5. Подтверждение

```
car.py watch set "Обороты=0:0C9:1.7:16:be*0.25@об/мин"        # живое значение на странице пользователя
car.py watch add "Кандидат2=0:3A0:2.0:16:le*0.125@об/мин"     # можно 2–3 кандидата сразу, до 12 полей
car.py watch values --count 5 --every 1                        # Claude сам видит значения
car.py ask "На экране «Обороты». Подними до 1500, потом до 2500. Совпадает с тахометром?" --buttons "Совпадает,Не совпадает,Не понял"
```

Критерий: совпадает с прибором минимум на двух уровнях, меняется плавно и синхронно. Для бита — переключается ровно
вместе с действием 3 раза подряд. Если «Не совпадает», спроси, какое значение на приборе (`--input number`), и вернись к анализу.
`car.py watch` печатает «ВНИМАНИЕ», если поле `be` через границу байта: прошивка такое не читает, для прошивки ищи копию в `le`.

## 6. Фиксация результата

1. `canhunt.py export latest --field SPEC --name rpm` выдаёт строку прошивки
   `{ ID, start_byte, start_bit, bit_len, is_signed, factor, offset, "NAME" }` (только для `le`) и строку DBC `SG_`.
2. Запиши находку в `${CLAUDE_PROJECT_DIR}/can_hunt_found/<марка_модель_год>.md` (создай, если
   нет): сигнал, spec, канал и скорость шины, период кадра, строка прошивки, как подтверждено (уровни, совпадение с
   прибором), папка сессии, дата. Туда же отрицательные результаты («в CAN0 педали нет»).
3. В конфиги и прошивку вписывай только по просьбе пользователя.
4. Коротко скажи пользователю итог (`car.py note` плюс сообщение в чат).

## 8. Стиль инструкций

- По-русски, коротко, **одно действие**, конкретные числа, в конце явное «Когда готово — нажми «…»».
- 1–3 предложения. Надпись кнопки — 1–3 слова. Почти всегда давай выход: «Не получается», «Не понял».
- Не проси одновременно смотреть на приборку и в ноутбук, если действие этого не требует.
- Хорошо: «Выжми педаль газа наполовину и держи. Когда держишь ровно — нажми «Держу 50%»».
- Плохо: «Сейчас мы проверим гипотезу про ID 0x0C9, для этого нажмите газ на разные уровни и сообщите результаты».
- Если пользователь ошибся (нажал не ту кнопку), закрой фазу (`phase -`) и повтори шаг с новым именем фазы (`rpm2000b`).

## 9. Потеря связи и сбои

- `car.py` → «монитор не запущен» (код 1): страница у пользователя тоже не работает. Напиши ему **в чат**: «Монитор закрылся,
  запусти UC_…_Monitor.exe и нажми «Совместная работа»». Потом `car.py status`. Идущая сессия при закрытии exe
  закрывается корректно. После перезапуска начни новую (`session start rpm2`) и повтори незаконченную фазу.
- `ask` → «монитор перезапускался — инструкция потеряна»: повтори `ask`.
- `ask`/`wait` → код 6 «связь с контроллером потеряна» или «сниффер выключен — кадры НЕ пишутся» (контроллер
  перезагрузился — например, просадка на стартере, — отошёл USB или 5 с не было хоста): напиши пользователю в чат
  проверить USB и питание, потом `car.py status`. Монитор переподключается сам и, если идёт запись, сам повторяет
  команды сниффера; если `status` показывает «сниффер выключен» — `car.py sniff on`. Страница пользователя в это время
  показывает красную плашку «ИДЁТ ЗАПИСЬ, НО …». Отрезок без кадров в анализе не участвует (`info` его покажет) —
  повтори незаконченную фазу. Короткий обрыв, который сам восстановился, `ask` отмечает строкой «прерывались ~N с».
- После запуска двигателя (стартер просаживает питание) и после любого переподключения — `car.py status`: сниффер ВКЛ,
  кадр/с > 0.
- `status` → «Контроллер: НЕ подключён»: USB или питание. Монитор переподключится сам, сессия продолжится (без кадров,
  пока связи нет).
- Кадров 0 / `lec=…` → скорость шины или подключение (§1, п. 4).
- «старая версия без совместной работы» → монитор без `/coach`; exe нужно пересобрать (`build_exe.bat` в папке монитора).
- «на порту N отвечает не монитор UC» → на этом порту другая программа: монитор тогда занимает следующий свободный
  (+1…+9) и пишет его в `%TEMP%\UC_<плата>_Monitor[_demo].port` — car.py при автопоиске читает этот файл; запусти
  car.py без `--port` / `UC_PORT` или укажи порт из файла.
- Вывод car.py — UTF-8. Если в консоли кракозябры, смотри вывод фонового задания как есть: он корректен.

## 10. Передача кадров (TX)

Сниффер умеет не только слушать, но и **слать кадры в шину** — как в любом CAN-сниффере. Это отдельный, явно
включаемый режим (SPEC §11). Сначала прочитай §0 про безопасность передачи: только на стоянке, осознанно, по одному
кандидату, с возвратом канала в тихий режим.

```
car.py active on --ch 0 --br 125        # перевести CAN0 в активный режим (Normal): канал начнёт ПИСАТЬ в шину (ACK + TX)
car.py tx 0 384 01FF00                   # передать кадр ID 0x384 с данными 01 FF 00 один раз
car.py tx 0 384 "01 FF 00"              # данные с пробелами — в кавычках; DLC берётся из длины данных
car.py tx 0 10A AABB --period 100        # слать периодически каждые 100 мс (без предела)
car.py tx 1 18DAF110 "02 10 03" --ext --period 200 --count 5   # 29-битный ID, 5 раз
car.py tx-list                           # активные каналы и слоты передачи (ID, период, сколько отправлено)
car.py tx-stop 1                         # остановить слот 1;  car.py tx-stop — остановить все
car.py active off --ch 0                 # вернуть канал в тихий режим (снова слушает молча)
```

- **Порядок всегда такой:** `active on` → `tx …` → (поработали) → `tx-stop` → `active off`. Без `active on` команда
  `tx` откажет с кодом 3 и подсказкой — car.py сам канал в активный режим НЕ переводит (это осознанное действие).
- В `status` активный канал показан как «АКТИВНЫЙ (передача) — пишет в шину» (вместо «молча»), плюс отдельная строка
  «ВНИМАНИЕ: … ПИШУТ в шину». Это не «НЕ ГОТОВО» — режим осознанный, но лишний раз проверь, что он действительно нужен.
- `ID` и `DATA` — в hex. 29-битный ID определяется автоматически (8 цифр или больше 7FF), либо задаётся `--ext`.
  `--fd` — кадр CAN FD (до 64 байт), `--brs` — с ускорением фазы данных. `--slot K` — занять конкретный слот 0..7
  (по умолчанию первый свободный); одинаковый слот заменяет содержимое. Минимальный период — 5 мс.
- **Умный перебор (реверс команд).** Чтобы найти, какой кадр за что отвечает, часто нужно не только слушать, но и
  слать: возьми уже виденный в шине кадр (из `canhunt.py overview` / `car.py` ленты монитора) и повтори его с
  изменёнными байтами/битами, наблюдая реакцию машины (свет, замок, приборка). Делай это по одному кандидату, короткими
  сериями, каждый раз возвращая исходное состояние. Подробные приёмы — в PLAYBOOK «Передача».
- Передача пишет в РЕАЛЬНУЮ шину машины: неверный кадр может, например, погасить приборку или вызвать ошибку в ЭБУ
  (обычно снимается зажиганием). Не шли в шину неизвестного назначения кадры вслепую там, где это может помешать
  безопасности; на движущейся машине передачу не ведём.

## 11. Шпаргалка car.py

```
car.py status [--json]
car.py sniff on [--ch N] [--br K] [--fd 0|1] [--dbr K] | sniff off [--ch N]
car.py active on --ch N [--br 125] [--fd 0|1] [--dbr K] | active off [--ch N]     # активный режим (передача) — ПИШЕТ в шину!
car.py tx CH ID DATA [--ext] [--fd] [--brs] [--period MS] [--count N] [--slot K]  # передать кадр (нужен active on)
car.py tx-list        car.py tx-stop [SLOT]
car.py session start NAME | session stop | session
car.py say TEXT [--buttons "Начал=rpm2000,Закончил=-,Не вышло"] [--input number|text --label TEXT]   # «|» вместо «,», если в надписи есть запятая
ask_chain.py STEPS.txt [--port N] [--timeout S]        # цепочка ask одним фоновым процессом (строка шага: ТЕКСТ || КНОПКИ)
car.py ask TEXT [те же опции] [--timeout 900]          # в фоне! 0 ответ / 2 таймаут / 4 сообщение / 5 заменена /
                                                       #          6 нет связи с контроллером / 1 нет монитора
car.py wait [--since SEQ] [--timeout S] [--types button,input,mark,note,link] | wait --say N
car.py events [--since SEQ] [--last N]
car.py phase LABEL | phase -        car.py mark [LABEL]        car.py note TEXT
car.py watch set|add "Имя=CH:ID:BYTE.BIT:LEN:ORDER[:s][*F][+O]@ед" … | watch clear | watch values [--count N --every S] | watch
Общие ключи: --port N (или UC_PORT), --json. \n в тексте инструкции — перенос строки.
```

Формат поля: `CH:ID:BYTE.BIT:LEN:ORDER[:s][*FACTOR][+OFFSET]`, где BIT 0 — младший бит байта; `le` — старт с младшего бита
значения (Intel), `be` — старт со старшего (Motorola, DBC). Примеры: `0:0C9:1.7:16:be*0.25`, `0:1F5:0.0:16:le*0.01`,
`0:2A0:1.4:1:le`, `0:3E0:0.0:8:le-40`.
