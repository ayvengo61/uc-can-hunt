==========================================================
 ЗАПУСК ДВОЙНЫМ КЛИКОМ: UC_G4_Monitor.exe
==========================================================

Запусти UC_G4_Monitor.exe. Python, pyserial и start.bat больше
не нужны. Программа сама:
 - находит COM-порт контроллера (USB, VID 0483; VCP от ST-Link
   и Bluetooth-порты пропускает);
 - читает JSON-кадры диагностики;
 - открывает дашборд в браузере: http://127.0.0.1:8473/

В окне программы видно: есть ли связь, номер порта, счётчик
кадров и журнал (порт открыт / контроллер уснул / порт занят).
Если автопоиск выбрал не тот порт, выбери COM вручную в списке
"Порт". Закрытие окна завершает монитор.

Когда контроллер засыпает и пропадает с USB, монитор ждёт и сам
подключается после пробуждения, даже если номер COM изменился.
Повторный запуск exe второй экземпляр не создаёт, а просто
открывает дашборд уже работающего.

Дашборд вшит в exe. Если рядом с exe лежит dashboard.html,
берётся он: правишь файл, обновляешь страницу в браузере.
Exe можно скопировать куда угодно одним файлом.

Пересборка (после правки uc_monitor.cs): build_exe.bat.
Нужен только Windows, компилятор csc.exe входит в систему.

Ключи командной строки (необязательные):
  --com COM7     конкретный порт вместо автопоиска
  --port 8600    другой HTTP-порт (по умолчанию 8473, если занят,
                 берётся следующий свободный из десяти)
  --no-browser   не открывать браузер при запуске

==========================================================
 CAN / CAN FD СНИФФЕР
==========================================================

Кнопка "CAN сниффер" в окне монитора или ссылка в шапке
дашборда открывает страницу /sniffer. Только приём: сниффер
слушает шину в режиме Bus Monitoring ("молча") и в неё ничего
не передаёт (в диагностике у такого канала "silent":1; car.py
status пишет "молча").

Три шины: CAN0, CAN1, CAN2.

Что нужно: прошивка контроллера с модулем app/can_sniff.c
(с 19.09.2026). Со старой прошивкой страница пишет
"прошивка без сниффера".

Включение по каналу:
 - канал всегда слушает шину в режиме Bus Monitoring: без
   подтверждения кадров (ACK), без кадров ошибок и без
   передачи — шину не трогает. Кадры TX конфига на этом канале,
   пока сниффер включён, тоже не уходят;
 - "как в конфиге" — скорость и FD из конфига;
 - своя скорость / FD / скорость данных — канал временно
   перенастраивается на них;
 - режим канала из конфига (Normal, с ACK) — только командой
   {"cmd":"sniff","ch":N,"on":1,"ack":1} (для стенда, где кроме
   контроллера некому подтверждать кадры).
   Скорости данных FD: 1000, 2000, 4000, 5000, 8000 кбит/с.

Выключение возвращает канал к параметрам конфига. Пока
сниффер включён, контроллер не засыпает; если монитор закрыли
или кабель вынули, сниффер через 5 с выключается сам.

Страница:
 - "По ID" — таблица: канал, ID, длина, данные, период,
   число кадров. Изменившиеся байты подсвечиваются (ярко —
   меньше 0.3 с назад, тускло — до 3 с). Флаги: 29 — 29-битный
   ID, FD/BRS, ESI, RTR. Клик по заголовку — сортировка.
 - "Лента" — кадры по порядку с временем и интервалом.
 - Фильтр: части ID через пробел (3E8 18DA*), ch0/ch1/ch2 —
   канал, !3E8 — исключить.
 - "Запись в файл" — лог в папку can_logs рядом с exe,
   формат candump (.log): открывается в SavvyCAN и can-utils.
 - Счётчик "потеряно" — кадры, которые не успели уйти в USB
   или переполнили аппаратный буфер контроллера.

Проверка без контроллера: UC_G4_Monitor.exe --demo
(кадры генерирует сам монитор).

Протокол (для своих программ): команда в порт
  {"cmd":"sniff","ch":0,"on":1,"br":500,"fd":1,"dbr":2000}
кадры из порта строками
  ~<канал><флаги> <ID hex> <данные hex | - | R<dlc>> <время мкс hex>


Старый способ (bridge.py + start.bat) оставлен как запасной,
описание ниже.

Редактор конфига в дашборде работает как раньше: команды уходят
в контроллер через exe, ответы cfg/resp возвращаются на страницу.


==========================================================
 UniversalController G473 — Web Dashboard
==========================================================

Веб-интерфейс показывает в реальном времени все основные
показатели контроллера: входы, выходы, DAC, CAN, LIN, Sleep.

==========================================================
 БЫСТРЫЙ СТАРТ (Windows)
==========================================================

1. Установить Python 3.8+ если нет
   https://www.python.org/downloads/

2. Установить зависимости (один раз):
     pip install pyserial

3. Подключить контроллер по USB

4. Запустить мост:
     start.bat
   или вручную:
     python bridge.py auto 8000

5. Открыть в браузере:
     http://localhost:8000

==========================================================
 ФАЙЛЫ
==========================================================

  bridge.py        — Python мост (читает COM, отдаёт HTTP)
  dashboard.html   — веб-страница (загружается мостом)
  start.bat        — запуск с автопоиском COM
  README.txt       — этот файл

Положите все файлы в одну папку.

==========================================================
 ПАРАМЕТРЫ ЗАПУСКА
==========================================================

  python bridge.py [COM_PORT] [HTTP_PORT]

Примеры:
  python bridge.py              # auto, port 8000
  python bridge.py auto         # автопоиск STM32, port 8000
  python bridge.py COM10        # вручную, port 8000
  python bridge.py COM10 8080   # вручную, port 8080

==========================================================
 ТРОЛБШУТИНГ
==========================================================

"STM32 COM-порт не найден":
  Скрипт ищет порты с VID 0483 (ST). Если найти не может,
  список покажется в консоли. Скопируйте имя и запустите:
     python bridge.py COM10

"connected" но frames=0:
  Контроллер не шлёт JSON. Проверь:
   - В config/diag_config.h:  DIAG_ENABLED 1
   - В app/app.c добавлены Diag_Init() и Diag_Tick()
   - Прошивка перезалита

"bridge offline" в браузере:
  bridge.py не запущен или другой HTTP_PORT.

Не открывается localhost:8000:
  Файрвол / антивирус / VPN могут блокировать.
  Попробуйте 127.0.0.1:8000 вместо localhost:8000.

==========================================================
 КАК ЭТО РАБОТАЕТ
==========================================================

  STM32 -- USB CDC -- COM-port -- bridge.py -- HTTP -- Browser
   (JSON 500ms)                   (хранит         (опрос
                                    последний       /data
                                    кадр)           500ms)

JSON формируется в app/diag.c. Период — DIAG_PERIOD_MS
(по умолчанию 500 мс).

==========================================================
 РЕДАКТОР КОНФИГА (Phase 4)
==========================================================

В дашборде внизу — карта "Configuration (runtime)":

  Load      — прочитать текущий конфиг с контроллера (get)
  Apply     — отправить изменённые поля (set) и применить (apply),
              с авто-сохранением во Flash
  Discard   — отменить правки (pending = active)
  Defaults  — залить дефолты в pending (затем нужен Apply)

Редактируются: входы, выходы, DAC, STOP, период диагностики,
делитель. CAN/LIN — только просмотр (меняются в прошивке).

Канал команд: браузер → POST /cmd → bridge.py → COM →
cmd_proc.c → config.c → драйверы (через *_OnConfigApplied).
Ответы контроллера ({"cfg":...}/{"resp":...}) мост отдаёт по
GET /cfg, мониторинг ({"uptime_ms":...}) — по GET /data.

==========================================================
ОБНОВЛЕНИЕ 2026-09-29: общий монитор G4 / H723 / H503
==========================================================
uc_monitor.cs, app.html и sniffer.html теперь одни и те же для трёх
плат (эталон — папка H_503/UC_H503_web). Плата выбирается при сборке:
/define:G4, /define:H723 или /define:H503 (build_exe.bat). Для G4/H723
поведение прежнее, добавлено:
  - /board: ещё "br", "dbr" (скорости сниффера) и "cfgBase" (у G4/H723 0);
  - /cfg?since=N и /cfg?rsince=N — все кадры cfg / resp после номера N
    (app.html так не теряет ответ get, если следом пришёл чужой кадр);
  - отдельный кадр {"sig":...} вклеивается в /data (у G4/H723 "sig" и так
    внутри основного кадра — ничего не меняется);
  - демо: свой конфиг для окна приложения — файл demo_cfg_<плата>.json
    рядом с exe (без файла демо как раньше);
  - окно приложения: «Инструменты» → «Конфигурация в файле» — сохранить
    конфиг в JSON и загрузить обратно (перед сменой прошивки/набора);
  - sniffer.html: короткий кадр diag_overflow не сбрасывает экран.
Прежние файлы — в истории git (G4) или в копии, сделанной при обновлении.
